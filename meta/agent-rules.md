# meta/agent-rules.md

Правила роботи LLM-агента в MATALY. Самодостатній документ, адаптований з KARCAS-DDA `meta/agent-rules.md` (v1.2) під потреби MATALY за `D-20261019-04`.

При конфлікті з `INVARIANTS.md` — пріоритет за `INVARIANTS.md`.

## 1. Нумерація відповідей

- Формат: `MS N` — окремим першим рядком відповіді, нічим не передується.
- Один номер на один ответ. Не нумерувати окремі кроки/задачі/блоки коду всередині одного ответа.
- Усередині блоків коду номер MS не ставиться.
- Нумерація наскрізна в межах одного чату, починається з 1, між задачами не скидається.

## 2. Формат відповідей

- Коротко, без води. Не роздувати.
- Один крок за раз. Не забігати наперед.
- Одна команда → вивід → наступна. Не стекувати команди навіть якщо вони логічно пов'язані.
- Промпти й команди — copy-paste одним блоком, без вкладених пояснень.
- Не повторювати відоме.
- Мова відповіді — мова запиту. Короткий запит — коротка відповідь, докладний — розгорнута.
- Кожне повідомлення споживає контекст. У довгих сесіях — економити.

## 3. Режими взаємодії

- «Обговоримо» / «поки обговорюємо» / «накидай ідею» — режим обговорення. Не видавати промпти, чернетки, команди, готові блоки. Лише аналіз, варіанти, позиція.
- Дії (промпти, команди, блоки, правки) — лише за явною командою.
- Обговорення ідеї не є командою діяти. Збирати блок — лише коли прямо попросили.
- «Один крок за раз» — не давати наступний крок до отримання виводу попереднього.
- Самовільні дії (створення, видалення, зміна файлів без команди) — порушення протоколу. Якщо дія здається потрібною — запропонувати, чекати рішення.
- Підтверджене оператором не перепитувати. Зайві уточнення замість дії — порушення протоколу.

### Fallback при відсутності оператора

Якщо агент виявив стан, що вимагає рішення, а оператор недоступний:

1. Не продовжувати залежні дії.
2. Зафіксувати стан у `CURRENT_STATE.md`, розділ «Заблоковано»: що виявлено, чому вимагає рішення, коли зафіксовано (дата з §7), за яких умов розблокується.
3. Позначити невизначене як `[НЕВІДОМО]` — не заповнювати припущенням.
4. Зупинитися. Не вирішувати конфлікт самостійно, не приймати рішення за оператора.

«Розумний час» — за контекстом: в інтерактивній сесії достатньо відсутності відповіді на два-три питання підряд; в асинхронному режимі — за ознакою, що залежні дії більше не можуть бути відкладені.

Якщо оператор з'явився після фіксації — почати з перевірки розділу «Заблоковано» в `CURRENT_STATE.md`, не з пам'яті.

## 4. Варіанти й рекомендації

- Не давати варіанти без рекомендації.
- Позначати вибір: `[ПРЕДПОЧТИТЕЛЬНО]`.

## 5. Робота з фактами

- Прямо й чесно, включно з обмеженнями.
- Не додумувати. Питати або позначати `[НЕВІДОМО]`.
- Явна атрибуція зовнішніх спостерігачів.
- Помилка в попередньому ответі — визнати прямо, відкотити, не захищати формулювання.
- Не задавати питань заради питання. Якщо відповідь очевидна з контексту або зафіксована в документі — не питати.

## 6. Робота з терміналом

- Команди — готові до вставки одним блоком, з позначкою `bash`.
- Результат команди — в чат.
- Не припускати, що оператор пам'ятає розташування файлів. Вказувати явно.
- Перед командою уточнювати `pwd`, якщо це значимо. Помилки «файл не знайдено» — часто через невірний каталог.
- Після `git push` — дочекатися `git log -1 --oneline` + `git ls-remote origin refs/heads/main` + `git status --short`. Не вважати успішним без підтвердження виводу і збігу SHA.

### Формат повідомлення коміту

Шаблон: `[роль / модель] документ: що змінено; підстава`

- Роль — одна з: Архітектор, ведучий, агент.
- Модель — вільне поле: Claude, DeepSeek, Kimi, Luna, Namazu, людина.
- Документ — цільовий файл або група файлів. Допускається одиниця запису `records/run-N/...`.
- Що змінено — короткий опис.
- Підстава — посилання на запис у `DECISIONS.md`, якщо застосовно.

Приклад:

    [ведучий / DeepSeek] INVARIANTS.md: уточнено I3, додано механізм разового виключення; D-20261014-05

Формат дає provenance правок через `git blame`.

### Робота з довгими файлами й heredoc

Heredoc ненадійний для вмісту, що сам містить:
- фенсед-блоки markdown (потрійні backtick);
- вкладені heredoc;
- рядки з підстановками shell (зворотні лапки, `$`).

Ознаки: команда «зависає», чекаючи EOF; вміст обрізається; у файл потрапляє сміття.

Правила:
- Розбивати вміст на кілька коротких блоків (`cat >` для першого, `cat >>` для наступних).
- Для файлів із фенсед-блоками — писати через `nano`/редактор, не через heredoc.
- Альтернатива: `python3 -c` з багаторядковим рядком, але це теж вимагає обережності.
- Після запису — завжди перевіряти `wc -l` і `tail -5` до продовження.

## 7. Дати

- Перед записом у файл, де потрібна дата, — отримати її через `date` у терміналі. Вивід — єдине джерело дати.
- Не виводити дату з контексту, попередніх відповідей, припущень про час сесії.
- Якщо дата ще не отримана — не писати документ, де вона потрібна, або ставити явну помітку `[ДАТА НЕ ЗАФІКСОВАНА]`.

## 8. Формат правки документів

- Формат правки — весь документ цілком, одним блоком, готовим до копіпасту.
- Не диф, не фрагмент «вставити після розділу X».
- Правки документів — лише за явною санкцією на кожну правку. Згода з чимось не є санкцією на редагування.
- Правки можуть накопичуватися в явному списку до окремої команди на комплексну редакцію.

**Виняток для append-only журналів.** Для документів, які за режимом є append-only (`DECISIONS.md`, `PROVENANCE.md`, `meta/transitions.md`, `meta/open-questions.md`, `records/`), повна видача документа марнотратна: існуючі записи не змінюються. Допускається фрагмент — «додати в кінець» з явною поміткою місця вставки.

**Виняток для новостворюваних файлів.** Коли файл створюється вперше, вміст уже є в контексті (щойно обговорювався). Повторна видача цілого документа дублює контекст. Допускається:
- запис через команду з коротким підтвердженням (`wc -l` + `tail`);
- для коротких файлів (до ~50 рядків) — цілком, без змін;
- для довгих — розбивати на блоки.

**Виняток для великих raw-вигрузок.** Якщо зовнішній вихід перевищує ~20 КБ:
- зберігати raw поза git-репозиторієм (наприклад, `~/raw-external/`);
- у `records/` зберігати мета-запис: шлях, розмір, sha256, дата, спостерігач;
- це не порушує I3 (первинні дані збережено), але економить контекст і місце в репо.

Вимога «документ цілком» залишається обов'язковою для змінюваних нормативних документів: `INVARIANTS.md`, `CURRENT_STATE.md`, `README.md`, `00_ENTRY.md`, `meta/agent-rules.md`, `meta/handoff-protocol.md`, `meta/handoff-current.md`, `docs/*.md`.

### Точкові правки змінюваних документів через патч

Для змінюваних документів при роботі з виконавцем, що має доступ до репозиторію, допускається альтернатива: правка у вигляді патча.

- Патч формується як diff-фрагмент із явним контекстом.
- Перед застосуванням: `git apply --check patch-file` — перевірка, що патч застосується без конфліктів.
- Тільки після успішної перевірки: `git apply patch-file`.
- Після застосування: `git diff` — підтвердження результату; коміт у форматі §6.

Патч не замінює повну видачу для великих правок. Для дрібних (один рядок, один розділ) — економить контекст. Для правок нормативних документів (`INVARIANTS.md`, `CLAUDE`) патч застосовувати не можна — лише цілий документ або гілка з рев'ю.

## 9. Зачистка сміття

- Тимчасові, тестові файли, чернетки запитів, проміжні експорти — видалити або явно позначити на видалення до звіту, не після.
- Якщо щось залишено навмисно — вказати причину в звіті.

## 10. Anti-patterns

Порушеннями протоколу вважаються:

- вигадування відсутнього стану проєкту;
- твердження, що файл прочитано, коли він не читався;
- твердження, що команда виконана, коли не виконувалася;
- твердження, що правка відбулася, коли її не було;
- звернення зі старим handoff як із поточним станом;
- видача власного аналізу за вивід зовнішнього спостерігача;
- приписування спостерігачу вигаданого висловлювання;
- мовчазне вирішення конфлікту джерел;
- мовчазна зміна сенсу рішення оператора;
- старт залежної операції при неперевіреному стані;
- «роби як раніше» без явно визначеної операції;
- реконструкція втраченого сирого матеріалу по пам'яті;
- самовільні дії без команди (створення, видалення, зміна);
- правка свого ж змінення тим самим агентом без зовнішньої перевірки;
- heredoc із фенсед-блоками або вкладеними підстановками shell;
- обхід закритого реєстру (SPA, API-ключ, Cloudflare) замість фіксації `[НЕВІДОМО]`;
- продовження роботи за відсутності оператора без фіксації в «Заблоковано»;
- вирішення конфлікту самостійно замість зупинки й запису `[НЕВІДОМО]`;
- зайві уточнення замість дії, коли оператор уже підтвердив.

До канонізації протоколу порушення трактуються як відмова протоколу, а не як стилістичний дефект.

Повний перелік anti-patterns і failure cases KARCAS-DDA — зовнішнє джерело: `shaenxxx-commits/karcas-dda`, `meta/agent-rules.md` §11 і `meta/handoff-protocol.md` §9–10. За потреби підключаються посиланням, не копіюванням (I14).

## 11. Передача контексту

- Передача між сесіями й агентами — через `meta/handoff-current.md` за форматом `meta/handoff-protocol.md`.
- Новий агент не приймає handoff на віру. Обов'язкові кроки старту — див. `meta/handoff-protocol.md`.
