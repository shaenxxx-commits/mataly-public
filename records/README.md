# records/

Первинні записи спостережень MATALY. Append-only: існуючі записи не змінюються. Застаріле не видаляється (I9), а переноситься в `ARCHIVE/` з датою й причиною.

Адаптовано з KARCAS-DDA `templates/README.md` (шаблон первинної записи) і Envoy `docs/FIELD-LOG-v0.2.md` (польовий журнал як методологічний орієнтир) за `D-20261019-05`.

## Призначення

Фіксувати первинні спостереження про поле дослідження (об'єкт — компанія «Світ Рослин» і галузеве середовище) з прослідковуваним провенансом (I5) і явними статусами знання (I4).

Запис — не аналітичний висновок, а первинний матеріал. Інтерпретація й гіпотези в записі присутні, але явно відокремлені від спостережень.

## Іменування

`NNN-slug.md`, де:
- `NNN` — тризначний порядковий номер (001, 002, ...). Наскрізний, не перевикористовується.
- `slug` — короткий латинський ідентифікатор (kebab-case), що описує об'єкт або тему.

Приклад: `001-svit-roslyn-official.md`, `002-market-segments.md`.

## Формат запису

Обов'язкові поля (у цьому порядку):

    FIELD: <поле дослідження / об'єкт / тема>
    DATE: <YYYY-MM-DD, з термінального date>
    OBSERVER: <ведучий / модель / людина>
    OBSERVATION: <що фактично спостережено>
    SOURCE: <точне джерело: URL, файл, коміт, документ>
    ACTION: <що було зроблено для отримання спостереження>
    RESULT: <що отримано: текст, знімок, цитата>
    INTERPRETATION: <інтерпретація спостерігачем, зі статусом>
    HYPOTHESIS: <гіпотези, що випливають, зі статусом>
    UNKNOWN: <що залишилося невідомим>
    NEXT STEP: <наступна дія або рішення>

Поля не пропускаються. Якщо вміст відсутній — явно `[НЕВІДОМО]` або `[НЕ ЗАСТОСОВНО]`.

## Маркування тверджень

Кожне твердження в полях `OBSERVATION`, `INTERPRETATION`, `HYPOTHESIS` маркується статусом (I4):

- `[ФАКТ]` — підтверджено джерелом, джерело названо.
- `[ПІДТВЕРДЖЕНО]` — SUPPORTED, перевірка неповна.
- `[ГІПОТЕЗА]` — припущення, джерело не підтверджує.
- `[НЕВІДОМО]` — даних немає.
- `[МОЯ ПОЗИЦІЯ]` — операційна або аналітична позиція спостерігача.
- `[ЗОВНІШНІЙ — <ім'я>]` — дослівний вивід зовнішнього спостерігача.

Підвищення статусу — лише за наявності джерела й фіксації переходу (I4).

## Провенанс

- `SOURCE` містить точне посилання: URL (з датою доступу, якщо це веб), шлях до файлу, SHA коміту, назву документа.
- Для великих зовнішніх вигрузок (> ~20 КБ) — сирий матеріал зберігається поза git-репозиторієм (наприклад, `~/raw-external/`), у записі фіксується: шлях, розмір, sha256, дата доступу (див. `meta/agent-rules.md` §8).
- Реконструкція втраченого сирого матеріалу по пам'яті заборонена (I4).

## Зв'язок із рішеннями й провенансом

- Запис, що призводить до рішення, посилається на `D-YYYYMMDD-XX` у полі `NEXT STEP` або `INTERPRETATION`.
- Запис, що фіксує перехід статусу знання, — посилається на `meta/transitions.md` (коли підключений).
- Запис не замінює `DECISIONS.md` і не є рішенням.

## Мінімальність

Краще один повний запис, ніж десять порожніх (I14). Запис створюється тоді, коли є реальне спостереження, а не наперед.
